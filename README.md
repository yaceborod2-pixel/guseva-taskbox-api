# Архитектура приложения `taskbox-api`

Учебный REST API сервис для управления задачами (To-Do list). 
Стек технологий: **Python 3.10+**, **FastAPI**, **SQLAlchemy** (ORM), **SQLite3**, **Pydantic**.

---

## 1. Файловая структура проекта

Структура построена по слоям. Каждый файл отвечает строго за свою задачу, чтобы код не превращался в «кашу».

```text
taskbox-api/
├── app/
│   ├── __init__.py          # Делает папку app Python-пакетом
│   ├── main.py              # Точка входа, запуск FastAPI и подключение роутеров
│   ├── database.py          # Настройка подключения к SQLite3 и сессий БД
│   ├── models.py            # Модели таблиц базы данных (SQLAlchemy)
│   ├── schemas.py           # Схемы валидации входящих и исходящих данных (Pydantic)
│   ├── crud.py              # Функции для работы с БД (Create, Read, Update, Delete)
│   └── routers/
│       ├── __init__.py
│       └── tasks.py         # Эндпоинты («ручки») для работы с задачами
├── taskbox.db               # Файл базы данных SQLite (создастся автоматически при запуске)
├── requirements.txt         # Список зависимостей проекта
└── README.md                # Инструкция по запуску проекта
```

---

## 2. Описание слоев (Как всё работает вместе)

1. **`database.py`** — открывает соединение с файлом `taskbox.db` и выдает сессию для каждого запроса.
2. **`models.py`** — описывает, как таблица `tasks` выглядит внутри базы данных SQLite.
3. **`schemas.py`** — проверяет данные от пользователя (например, чтобы заголовок задачи не был пустым) и форматирует ответ сервера.
4. **`crud.py`** — содержит чистые Python-функции, которые делают запросы в базу (добавить запись, найти по ID, удалить).
5. **`routers/tasks.py`** — принимает HTTP-запросы от клиента, вызывает функции из `crud.py` и возвращает ответ.
6. **`main.py`** — собирает приложение воедино и подключает роутер из `tasks.py`.

## 3. Структура базы данных (SQLite3)

В базе данных будет всего одна таблица **`tasks`**:

| Поле | Тип данных в SQLite | Описание |
| :--- | :--- | :--- |
| `id` | `INTEGER` (Primary Key) | Уникальный номер задачи (заполняется сам) |
| `title` | `TEXT` (Not Null) | Название задачи (обязательное поле) |
| `description` | `TEXT` (Nullable) | Подробное описание задачи (необязательное) |
| `is_completed`| `BOOLEAN` (Default: False)| Статус выполнения (`False` — в работе, `True` — готово) |
| `created_at` | `DATETIME` | Дата и время создания задачи (ставится автоматически) |

## 4. Описание эндпоинтов («ручек») API

Базовый префикс для всех запросов: `/api/v1/tasks`

| Метод | URL (Ручка) | Что делает | Тело запроса (JSON) | Успешный ответ |
| :--- | :--- | :--- | :--- | :--- |
| **POST** | `/api/v1/tasks/` | Создает новую задачу | `{"title": "Купить молоко", "description": "2.5%"}` | `201 Created` + объект задачи с `id` |
| **GET** | `/api/v1/tasks/` | Возвращает список всех задач | *Нет* | `200 OK` + массив задач `[...]` |
| **GET** | `/api/v1/tasks/{task_id}`| Получает одну задачу по её `id` | *Нет* | `200 OK` + объект задачи (или `404`) |
| **PUT** | `/api/v1/tasks/{task_id}`| Полностью обновляет задачу | `{"title": "Новое", "description": "...", "is_completed": true}` | `200 OK` + обновленная задача |
| **PATCH**| `/api/v1/tasks/{task_id}`| Частично обновляет задачу (например, только статус) | `{"is_completed": true}` | `200 OK` + обновленная задача |
| **DELETE**| `/api/v1/tasks/{task_id}`| Удаляет задачу по её `id` | *Нет* | `204 No Content` (пустой ответ) |

Для старта проекта понадобятся всего три библиотеки:

```text
fastapi>=0.110.0
uvicorn>=0.29.0
sqlalchemy>=2.0.0
```

---

## 6. Команда для запуска

После написания кода сервер запускается из корневой папки `taskbox-api` командой:

```bash
uvicorn app.main:app --reload
```
После запуска интерактивная документация (Swagger) для тестирования всех ручек будет доступна по адресу: `http://127.0.0`
